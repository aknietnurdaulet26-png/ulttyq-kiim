# Ұлттық киімді құрастыр

Готовый статический образовательный проект для урока «Көркем еңбек»: 15 уровней, 61 действие с одеждой, 10 видов национальных костюмов, SVG-персонажи, учительская панель и LIVE-табло.

**Сайт подготовлен к размещению, но не подключён к вашему Firebase и не опубликован в вашем GitHub.** Перед совместной игрой нужно один раз создать бесплатный Firebase-проект, вставить его публичную конфигурацию, импортировать каталог и правила, назначить учителя. Без этих действий главная страница и справочник открываются, а онлайн-страницы показывают понятное сообщение о настройке. Фиктивных результатов в проекте нет.

## 2. Бесплатный Firebase

1. Откройте https://console.firebase.google.com/ и выберите **Create a project / Создать проект**.
2. Назовите его, например, `ulttyq-kiim`. Для этого проекта Google Analytics не нужен; его можно не включать.
3. Используйте тариф **Spark**. Не подключайте биллинг ради этого проекта.
4. В **Project overview → Add app → Web (значок </>)** зарегистрируйте веб-приложение. Firebase Hosting включать не нужно: хостингом будет GitHub Pages.
5. В **Project settings → General → Your apps → SDK setup and configuration → Config** скопируйте конфигурацию.
6. В файле `js/firebase-config.js` заполните ВСЕ пять полей:

```js
export const firebaseConfig = {
  apiKey: 'значение apiKey из консоли',
  authDomain: 'ваш-проект.firebaseapp.com',
  databaseURL: 'ТОЧНЫЙ URL вашей Realtime Database',
  projectId: 'ваш-projectId',
  appId: 'значение appId из консоли'
};
export const USE_EMULATORS = false;
```

Не копируйте буквальный пример выше. Вставьте реальные значения своего проекта. `authDomain` оставьте из конфигурации Firebase; не заменяйте его на адрес GitHub Pages. URL базы можно получить после следующего шага; он зависит от региона и может оканчиваться на `.firebasedatabase.app` или `.firebaseio.com`.

Эта конфигурация предназначена для открытого веб-кода. Она **не является административным ключом**. JSON сервисного аккаунта, приватные ключи, OAuth-токены и пароли публиковать нельзя. В приложении их нет.

### Realtime Database и каталог

1. **Build → Realtime Database → Create Database**.
2. Выберите регион. Начните в **Locked mode / заблокированном режиме**, не в Test mode.
3. Скопируйте URL базы в `databaseURL`.
4. Если база НОВАЯ И ПУСТАЯ: на вкладке **Data** выберите корень базы → меню ⋮ → **Import JSON** → `database.seed.json`.
5. В корне должен появиться узел `catalog`, внутри — `v1`, затем `steps`, `items`, `slots`. `steps` содержит ключи от `0` до `60`.
6. Вкладка **Rules**: полностью вставьте содержимое `database.rules.json` и нажмите **Publish**.

**Не импортируйте `database.seed.json` в корень существующей базы с данными: импорт заменяет выбранный узел.** Если база уже используется, добавьте отдельный узел `catalog` и импортируйте `catalog.seed.json` именно в него. Не меняйте узлы `rooms`, `teachers`, `teacherRooms`.

Каталог читается авторизованными клиентами, но никто из браузера не может его редактировать. Не меняйте `js/levels.js` отдельно от каталога: после изменения заданий запустите `node tools/build-rules.mjs`, обновите правила и заново импортируйте каталог. Не меняйте задания посреди активного урока.

### Authentication

1. **Build → Authentication → Get started → Sign-in method**.
2. Включите **Email/Password**. Вход по email-ссылке не нужен.
3. Включите **Anonymous**. Ученики входят без собственной электронной почты.
4. **Authentication → Settings → Authorized domains → Add domain**: добавьте `USERNAME.github.io` — без `https://`, без пути `/REPOSITORY/`.
5. Если тестируете локально, отдельно добавьте `localhost`. При будущем своём домене добавьте и его.

### Учётная запись учителя и права

1. В **Authentication → Users → Add user** создайте учителя с его электронной почтой и надёжным паролем.
2. Скопируйте **UID** созданного пользователя.
3. В **Realtime Database → Data** добавьте узел `teachers`, внутри ключ с ТОЧНЫМ UID учителя и значением логического типа `true`:

```json
{
  "teachers": {
    "ТОЧНЫЙ_UID_ИЗ_AUTHENTICATION": true
  }
}
```

Добавьте узел через интерфейс, а не импортируйте этот фрагмент поверх корня базы. Значение — boolean `true`, не строка `"true"`.

4. Откройте `teacher.html` и войдите этой почтой и паролем.
5. Создайте комнату. Если появилась ошибка с UID, проверьте назначение в `/teachers/UID`.

Одна лишь регистрация Email/Password НЕ даёт роль учителя. Ученик не может записать себе `/teachers/UID = true`. Только назначенный учитель может управлять СВОИМИ комнатами. Второй учитель не управляет чужими комнатами.

## 4. Как провести урок с 30 учениками

1. На компьютере учителя откройте `teacher.html` и войдите.
2. Введите название занятия → **«Бөлме жасау»**. Появится случайный шестизначный код.
3. Нажмите **«LIVE-таблоны ашу»**. На отдельной вкладке откроется `screen.html?room=КОД` с QR-кодом.
4. Покажите эту вкладку на интерактивной доске. Нажмите **«Толық экран»**. Если браузер устройства не поддерживает Fullscreen API, используйте его штатный полноэкранный режим (на ПК обычно F11).
5. Если доска — отдельный компьютер, войдите на ней ТЕМ ЖЕ учительским аккаунтом. Вход на доске обязателен: код комнаты сам по себе не даёт постороннему доступ к списку детей.
6. Ученики сканируют QR. Откроется `game.html?room=КОД`; код подставится автоматически. Альтернатива — открыть сайт вручную и ввести код.
7. Каждый ученик вводит имя и класс. Желательно использовать имя и инициал фамилии, если полный список не требуется.
8. В учительской панели сравните имена с классом, нажмите **«Растау»** напротив ученика или **«Барлығын растау»**.
9. Нажмите **«Ойынды бастау»**. Неподтверждённые ученики остаются в ожидании; их можно подтвердить позднее.
10. Ученики выбирают одежду и помещают её в указанную зону. На телефоне доступны перетаскивание и последовательные нажатия: сначала одежда, потом зона.
11. LIVE-табло получает изменения через `onValue()`; перезагрузка страницы и F5 не нужны.
12. **«Тоқтату»** ставит игру на паузу, **«Жалғастыру»** продолжает. Сервер отклоняет игровые действия во время паузы.
13. **«Сеансты аяқтау»** закрывает игру: табло показывает трёх лидеров, поздравление и полную таблицу. Завершённый сеанс нельзя продолжить, можно начать новый круг.
14. **«CSV жүктеу»** скачивает результаты с поддержкой кириллицы для Excel. Экспорт включает имя, класс, баллы, уровень, ошибки и бонусы. Строки защищены от формул CSV.
15. **«Жаңа айналым»** сбрасывает текущий раунд: ученики начинают с нуля и требуют нового подтверждения. Предыдущий раунд остаётся в базе (`rooms/КОД/players/НОМЕР_РАУНДА`). Перед сбросом удобно скачать CSV.

На одном устройстве у одного ученика должна быть одна игровая вкладка. Для проверки учителя и ученика на одном компьютере используйте разные профили браузера или приватное окно: обычные вкладки одного сайта делят Authentication-сессию.

### Вместимость и бесплатные лимиты

У Spark для Realtime Database лимит 100 одновременных подключений. 30 учеников + панель учителя + LIVE-табло укладываются в него. Одна лишняя вкладка может означать отдельное подключение. Это не гарантия скорости школьного Wi-Fi: проверьте сеть до урока. Следите за квотами в Firebase Console; при исчерпании бесплатного лимита сервис может перестать обслуживать запросы.

Firebase также ограничивает создание новых аккаунтов с одного IP: опубликованный лимит — 100 в час. 30 новых учеников обычно укладываются, но несколько классов подряд и много приватных вкладок могут достигнуть лимита. Сохраняйте сессии браузера; при необходимости заранее запросите временное повышение лимита в консоли. Не создавайте ученикам по новому аккаунту после каждого уровня.

## 5. Прогресс и смена устройства

- Каждый принятый ход записывается в RTDB отдельно. UI подтверждает баллы после завершения транзакции.
- В том же браузере Firebase сохраняет вход; повторный вход в ту же комнату восстанавливает прогресс. Повторная отправка и параллельные вкладки не добавляют один шаг дважды.
- Чтобы сменить устройство, ученик нажимает **«Прогресті басқа құрылғыға көшіру»** и сохраняет личный ключ. На другом устройстве вводит комнату и открывает **«Басқа құрылғыдағы прогресті қалпына келтіру»**.
- Технически эта дополнительная возможность связывает анонимный UID со случайным адресом в зарезервированном домене `students.invalid` и случайным длинным паролем. Реальная почта ученика не запрашивается, письма не отправляются. В Firebase для этого нужен включённый Email/Password.
- Ключ является секретом входа, а не общим кодом комнаты. Не показывайте его на доске. Он хранится локально только для владельца сессии; на общих устройствах его не следует сохранять.
- Если пользователь очистил браузер до сохранения ключа, анонимный доступ нельзя восстановить по одному имени. Не допускается небезопасное «восстановление» по ФИО. Учитель может принять новое участие; старую запись не следует выдавать за новую.
- После восстановления закройте старую игровую вкладку. Оба устройства имеют один UID и общий прогресс, а не независимые баллы.
- Для игры нужен интернет. При обрыве соединения действия отключаются; приложение не начисляет «офлайн-баллы», которые можно подменить при синхронизации.

## 6. Баллы и честность: что действительно защищено

Правильный следующий элемент и правильная зона: **+10**. Неверное сочетание: **−2**, с увеличением счётчика ошибок. Допускается отрицательный счёт. На каждом уровне есть бонус **+5** за быстрое завершение. Максимум: `61 × 10 + 15 × 5 = 685`.

Уровни идут последовательно, элементы внутри уровня тоже: текущая задача названа на экране. Длительность уровня начинается с первой попытки, включая ошибочную, а не с момента загрузки страницы. Паузы учителя вычитаются. Серверная граница бонуса — 60 секунд; клиент запрашивает бонус до 59 секунд, оставляя запас на передачу запроса. Вблизи границы бонус может не выдаваться. Для точного начисления по времени получения каждого запроса нужен отдельный backend.

### Бесплатная реализация

Здесь используется **серверная валидация Firebase Security Rules**, а не только JavaScript-проверка. Правила:

- запрещают всем клиентам назначать учителей и менять эталонный каталог;
- не дают одному ученику записывать состояние другого;
- проверяют текущий раунд, состояние игры и подтверждение учителя;
- разрешают ровно один следующий шаг, а не произвольный номер уровня;
- проверяют правильность элемента и зоны по защищённому каталогу;
- сверяют точные изменения баллов, ошибок и бонусов со старым состоянием;
- используют серверный `now`, проверяют время и минимальный интервал действий;
- запрещают удалять свою запись и начинать заново для стирания ошибок;
- отклоняют произвольное увеличение баллов и повторное начисление завершённых шагов.

Изменение HTML или локального JavaScript может поменять цифру на СВОЁМ экране, но не позволит записать произвольный результат в базу, если опубликованы приложенные правила. Другие устройства показывают данные RTDB.

### Важное ограничение

Это **не полная защита от читинга**. Клиент видит задания и способен автоматизировать корректные запросы, не отправлять свои ошибочные попытки или пройти шаги ботом. Security Rules проверяют допустимость переходов, но не могут доказать, что человек действительно перетащил одежду. Подтверждение учителем предотвращает случайное массовое участие, но не является защитой от DDoS и всех злоупотреблений квотами.

Для бесплатного формирующего оценивания подходит эта схема: авторизация + подтверждение учеников + проверяемые сервером переходы + наблюдение учителя. Для контрольной работы или конкурса с требованиями строгой честности нужна доверенная серверная система: закрытый каталог/задания, серверная обработка каждого действия, ограничения частоты и регистрация попыток. Firebase Cloud Functions требуют **Blaze и платёжного аккаунта**; бесплатная квота Blaze не означает гарантированно бесплатную эксплуатацию. GitHub Pages сам серверный код не исполняет. Другой вариант — backend на уже доступном школьном сервере с проверкой Firebase ID-токенов, но его обслуживание выходит за рамки статического GitHub Pages-проекта. Не переводите базу в открытый режим ради обхода ошибок.

## 7. Свой домен в будущем

1. Сначала убедитесь, что сайт работает на `USERNAME.github.io`.
2. В GitHub **Settings → Pages → Custom domain** укажите принадлежащий вам домен или поддомен.
3. Для поддомена, например `game.school.kz`, в DNS создайте **CNAME → USERNAME.github.io** (без протокола и имени репозитория).
4. Для корневого домена настройте записи по текущей официальной инструкции GitHub. Не копируйте IP из случайного старого руководства.
5. Дождитесь проверки DNS и сертификата, включите **Enforce HTTPS**.
6. Добавьте новый домен в **Firebase Authentication → Settings → Authorized domains**.
7. Откройте LIVE-табло уже на новом домене: QR автоматически будет содержать текущий адрес.
8. Учтите: смена домена меняет хранилище браузера. Ученикам, которым нужно сохранить UID, заранее выдайте возможность сохранить личный ключ.

Сам адрес `USERNAME.github.io` предоставляется GitHub. Регистрация отдельного домена обычно оплачивается владельцем; она не нужна для бесплатного запуска.

- [ ] До подтверждения играть нельзя; после подтверждения и запуска можно.
- [ ] Правильное действие даёт +10, неверное −2.
- [ ] Изменение видно на доске без F5.

### Автоматические тесты для разработчика

Для публикации они НЕ обязательны. Для запуска нужны Node.js 22, Java 17+ и доступ к скачиванию официальных эмуляторов Firebase.

```bash
npm ci
npm test
npm run test:ui
npm run test:rules
```

`test:rules` запускает Authentication и Realtime Database Emulator, проверяет права, 15 уровней и 30 одновременных клиентов. Используется только тестовый проект `demo-ulttyq-kiim`; ваши реальные данные не затрагиваются. Сообщения `permission_denied` внутри этого теста ожидаемы: это проверки запрещённых действий. Главный итог — код завершения 0 и прошедшие тесты.

`test:ui` запускает настоящий модуль игры в JSDOM с тестовым транспортом: проверяет привязку кнопок и Pointer Events. Это не заменяет проверку настоящего сенсорного браузера. `tools/run-local-tests.mjs` отключает proxy-переменные только для процесса тестов локальных эмуляторов, чтобы запросы на loopback не уходили во внешний прокси.

Для просмотра сайта локально используйте любой статический HTTP-сервер или Live Server в редакторе. Открытие `file:///.../index.html` не подходит для ES-модулей. Для локальных эмуляторов установите `USE_EMULATORS = true` только в локальной копии, загрузите тестовый каталог и создайте тестовые учётные записи. Перед публикацией обязательно верните `false`.

## 9. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| «Firebase әлі бапталмаған» | Все 5 полей `js/firebase-config.js`, затем commit и завершение публикации |
| `auth/operation-not-allowed` | Включены Anonymous и Email/Password |
| `auth/invalid-api-key` | Скопирована конфигурация именно Web App вашего проекта |
| Учитель не получает права | Правильный UID в `/teachers/UID`, boolean true, вход именно этой учётной записью |
| `PERMISSION_DENIED` при игре | Правила опубликованы, `catalog/v1` импортирован, ученик подтверждён, игра запущена |
| Бесконечное ожидание сети | URL RTDB и интернет; школьная сеть должна разрешать Firebase |
| На доске нет участников | Правильный код, тот же владелец комнаты, подтверждение учеников |
| 404 на GitHub Pages | `index.html` лежит в корне main, источник Pages main/(root) |
| Нет CSS или SVG | Загружены папки целиком, имена и регистр файлов не изменены |
| Полный экран недоступен | Ограничения браузера устройства; используйте штатный режим браузера |
| Нет звука | Нажмите «Дыбыс: өшірулі» для включения, проверьте беззвучный режим устройства |
| Бонус не выдан на границе минуты | Серверное время и запас на передачу; бонус не является гарантией при задержке сети |
